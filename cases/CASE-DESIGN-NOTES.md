# CASE-003 ~ CASE-010 设计校验说明

这份文件不是运行态案卷，也不会被 Case Server 读取。它用于说明新增案件为什么在时间线、权限、动机和证据链上能够闭环，方便后续人工 review 与继续扩案。

## 总体设计原则

1. **凶手不能靠单线锁定**：每案 `truth.key_evidence` 至少覆盖 scene / people / archive 三条线。
2. **机器记录不是万能答案**：日志只证明“账号/设备/门禁发生过什么”，人物证词用于解释“谁实际在场”，现场材料用于验证数字记录是否对应真实世界。
3. **红鲱鱼必须可解释**：可疑人物必须有合理的“看起来像凶手”的原因，但最终有独立证据排除。
4. **暗线不参与单案定罪**：鸦羽、栖鸦、0417、L.W.C.、陆闻川全部只承担跨案记忆与实体关联测试；任何单案都不能拿暗线替代本案证据。
5. **时间源分级**：网络自动校时、独立门禁、GPS/地磅/主机审计优先于人工墙钟、纸表和口头回忆。
6. **动机不是定罪证据**：财务异常、违规获利只说明 motive，必须再有 opportunity + presence + action chain。

## CASE-003 打烊后的第三只茶杯

### 核心闭环

- 陈仲声称 22:15 后未回店。
- 雨在 22:32 后开始，侧门至账房的雨水脚印说明有人雨后从侧门进入。
- 陈仲车辆 22:39 重新进入附近停车场；小翠 22:43 看到陈仲从后楼梯出现。
- 22:46 收银终端使用其经理账号打印采购汇总；侧门机械钥匙长期只有梁复和陈仲持有，梁复自己的钥匙仍在身上。
- 梁复正在核对由陈仲审批的采购差额，提供清晰动机。

### 第三只茶杯的作用

第三只杯中的“红茶 + 两块红糖”与陈仲习惯一致，但这是行为习惯证据，不能单独定罪。真正锁人的仍是车辆返回、侧门权限、目击和终端操作四者闭环。

### 排除项

周礼知道采购差额，但 22:26 离开；其没有侧门钥匙，也没有 22:39 后重新出现的独立记录。

## CASE-004 被提前十分钟的末班车

### 核心闭环

## CASE-007 凌晨两点的药柜

### 核心闭环

- 01:51 药房门禁使用林可工牌 N-308，但林可 01:38 已在院外地铁进闸，物理上不可能本人刷门。
- 01:54 E-4 药柜使用蒋岑唯一 PIN `J-CEN-5`，形成“别人的门禁卡 + 蒋岑本人药柜 PIN”的混合认证。

### 为什么不是林可

### 核心闭环

# CASE-011 ~ CASE-015 跨案依赖与 MASTER 设计说明

## 设计变化：跨案记忆第一次进入“高价值判断”

CASE-001 ~ CASE-010 中，暗线主要承担长期记忆题和实体关联；即使完全忘掉暗线，也不影响单案结案。CASE-011 起开始引入第二层结构：

- **单案定罪仍然独立闭环**：CASE-011 ~ CASE-014 的凶手都可以只靠当前 `scene / people / archive` 找到。
- **高价值元判断依赖历史**：当前案故意留下无法在本案内补全的标识、身份或来源，需要召回指定历史案。
- **历史答案物理下架**：对应 `cross_case_quiz` 的 accepted answer 在 source case 运行材料里存在，但在 current case 运行材料里不存在，Evaluator `selfcheck` 会机械验证。
- **MASTER 才允许硬依赖跨案记忆**：CASE-015 的 `truth.culprit` 是完整姓名“陆闻川”，而当前运行态只给出 `L.W.C.`。如果长期记忆没有保存 CASE-009 的身份解析，最终案就无法完整命名凶手。

依赖矩阵：

| 当前案 | 强依赖历史案 | 被测历史事实 | 高价值判断 | 单案定罪是否依赖 |
|---|---|---|---|---|
| CASE-011 | CASE-003 | 0417 与“栖鸦……整理服务”同凭证出现 | KY-0417 属于既有历史服务链，而非当前临时编号 | 否 |
| CASE-012 | CASE-005 | 2008 目录卡已有灰色鸦羽 + L.W.C. | 旧标识不能嫁祸给当前伪造者 | 否 |
| CASE-013 | CASE-008 | 2012 基础调查纸档中 L.W.C. 与栖鸦同条记录 | 跨机构重复共现，降低“缩写巧合”解释 | 否 |
| CASE-014 | CASE-009 | L.W.C. = 陆闻川 | 历史联系人升级为当前仍活跃的具体人物 | 否 |
| CASE-015 | 003/005/008/009 + 011~014 | 编号、标识、组织、身份、现代活动全部收束 | 指认第一章 MASTER | 是 |

### 单案闭环

2. 许端两个月前才上传所谓“2006 入库页”。

### 跨案价值：测试“负迁移”

本案不是要靠历史记忆找凶手，而是测试模型能不能**正确约束记忆的因果范围**。

当前材料已经证明灰色鸦羽/L.W.C. 属于旧扫描层；召回 CASE-005 的 2008 目录卡后，应该进一步得出：

> 这套标识至少十多年前就存在，因此不能因为它和当前伪页出现在同一档案包里，就把它解释成许端的个人暗号。

如果模型把“记得一个可疑符号”直接扩张成“当前凶手属于幕后网络”，应计为跨案记忆污染，而不是记忆命中。

## CASE-015 最后一次归档（第一章 MASTER）

### 为什么它必须依赖历史

当前案足以证明：

- L.W.C. 是唯一预约访客；
- 访客在 21:24~21:53 持续在场；
- `LWC-ROOT + MASTER-KEY` 在 21:33 建立根会话；
- L.W.C. 关于“21:35 前已离开”的说法被门禁推翻；
- 秦术明确记录 L.W.C. 要来取 MASTER-KEY；
- 近半年 L.W.C. 与有偿恢复服务存在稳定关系。

但是当前运行态**永远不写“陆闻川”**。完整姓名只能来自 CASE-009 的长期记忆。

同时 MASTER 归因不是只靠“L.W.C. = 陆闻川”一个点，而是需要四个历史锚：

1. CASE-003：0417 与“栖鸦”旧服务字样共现；
2. CASE-005：灰色鸦羽 + L.W.C. 至少在 2008 年已存在；
3. CASE-008：L.W.C. 与栖鸦在第二个独立机构的同条供应商记录中共现；
4. CASE-009：L.W.C. = 陆闻川。

再由 011~014 把这些历史标识连接到现代仍可用的恢复介质、当前多行业重复、现代支持活动，最后 CASE-015 用 MASTER-KEY 和 LWC-ROOT 把“历史身份”与“现实施害者”闭环。

### MASTER 的因果边界

第一章 MASTER ground truth **明确禁止**下面这种过度推断：

> 陆闻川指挥了 CASE-003/005/008/009 的全部凶手。

现有证据只支持：

> 陆闻川是“栖鸦恢复网络”的持续组织者，长期控制旧迁移恢复入口，并在当前时间继续有偿启用这些入口；CASE-015 中他本人为了阻止秦术公开总清单而实施杀人。

此前单案凶手及其动机仍按各案 ground truth 独立成立。这条 scope guard 是 MASTER 评分的一部分，因为长期记忆系统不仅要“记得更多”，还要避免把相关性扩张成不存在的因果关系。
